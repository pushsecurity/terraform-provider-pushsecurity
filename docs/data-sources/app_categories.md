# pushsecurity_app_categories (Data Source)

Resolves app category names to the numeric codes that the `app_categories` criterion matches on.

~> There is no API that lists the category catalogue, so this is derived from the categories actually attached to the tenant's apps. A category that no app in the tenant belongs to will not appear here. Terraform fails on a missing map key, so a lookup for such a category fails during plan.

## Why this exists

The `app_categories` criterion matches on numeric category codes. A rule that
says `matches = ["34"]` is unreviewable: nobody reading the pull request knows
what category 34 is. This data source turns it into
`codes_by_name["Information Technology"]`.

## Example usage

```terraform
data "pushsecurity_app_categories" "all" {}

# The app_categories criterion matches on numeric codes. Writing
# matches = ["34"] in a pull request tells a reviewer nothing; looking the code
# up by name does. Fails during plan if no app in the tenant has the category.
output "information_technology_code" {
  value = data.pushsecurity_app_categories.all.codes_by_name["Information Technology"]
}

# Use the lookup in a rule of a control you have already imported:
#
#   criteria = {
#     app_categories = {
#       matches = [data.pushsecurity_app_categories.all.codes_by_name["Information Technology"]]
#     }
#   }
#
# Import the control before you add it to your configuration. A control
# resource owns the whole control, so applying one you have not imported
# replaces every rule the tenant already has.

# Categories are derived from the apps in the tenant, so this shows what is
# actually resolvable.
output "categories_in_use" {
  value = data.pushsecurity_app_categories.all.categories
}
```

## Derived, not authoritative

There is no API that lists the category catalogue. The app inventory reports
each app's categories with both code and name, so this data source derives the
mapping from the apps in the tenant — which means **a category that no app in
the tenant belongs to does not appear here**.

That is a real limitation, but a safe one: Terraform fails on a missing map key,
so looking up an absent category fails during plan with a clear error rather
than silently producing an empty criterion. Use the `categories` attribute to
see what is resolvable.
