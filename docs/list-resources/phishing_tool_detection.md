# pushsecurity_phishing_tool_detection (List Resource)

Finds the phishing tool detection configuration, to adopt with `terraform query`. There is one per tenant, so this returns at most one result, and none when the control has no rules and no control-wide entries.

List resources need Terraform 1.14 or later.

## Example usage

Put the list block in a file ending in `.tfquery.hcl`, beside your
configuration:

```terraform
list "pushsecurity_phishing_tool_detection" "adopted" {
  provider = pushsecurity
}
```

Then let Terraform write the resource and its import block:

```shell
terraform query -generate-config-out=generated.tf
```

- **Every list block needs `provider = pushsecurity`**, or the query
  fails.
- **Keep the `provider` block and `required_providers` in a `.tf` file.** A
  `.tfquery.hcl` file cannot hold a `terraform` block. A `provider` block in
  one is used by the query alone, and plan then configures the provider without
  it.
- **`generated.tf` must not exist yet.** Terraform only writes generated
  configuration to a new file.

Move the generated resource into your configuration and run `terraform apply`
to record the import. Leave the `provider` argument on the resource and the
import block: the plan accepts both. The resource is named `adopted_0`. Rename
it before the first apply, or with a `moved` block after.

Give every rule a stable `key` while adopting it. Generated rules have
`key = null`, because keys exist only in Terraform and cannot be recovered from
the API.

## Warnings

When the tenant holds configuration that the first plan will reject or warn
about, the result carries a warning, named after the resource, that lists each
rule and value at fault. The API can return configuration that it refuses on
write, and the provider checks some values more strictly than the API does.
There are two warnings:

- **`configuration the first plan will reject`**: the configuration Terraform
  generates fails plan until it is fixed.
- **`configuration that plans with a warning`**: Terraform accepts it, but the
  value does not match the way it reads.

Fix them as part of adopting the resource. The plan reports each one against
the attribute at fault.
