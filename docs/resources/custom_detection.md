# pushsecurity_custom_detection (Resource)

Manages a custom detection: the detection logic the browser extension evaluates, and the rules that decide what happens when it matches.

`detection_logic` is stored and returned byte for byte, so keeping it in a file and reading it with `file()` gives you detection-as-code with no normalisation surprises.

A create the API does not answer in time may still finish afterwards, so the provider then waits up to two minutes for the detection to appear, and adopts it if it holds the planned logic and rules.

## Example usage

```terraform
resource "pushsecurity_custom_detection" "torrent_website_visit" {
  name = "Torrent website visit"

  # The API stores and returns this byte for byte, so keeping detection logic in
  # its own file gives you detection-as-code with no normalisation surprises:
  # a plan is empty unless the file actually changed.
  detection_logic = file("${path.module}/detections/torrent-website-visit.yaml")

  rules = [
    {
      key      = "block-contractors"
      name     = "Block torrent sites for contractors"
      enabled  = true
      mode     = "BLOCK"
      severity = "HIGH"
      title    = "Blocked"
      subtext  = "Torrent sites are not permitted on company devices."

      criteria = {
        employee_groups = { matches = ["Contractors"] }
      }
    },
    {
      key         = "warn-everyone-else"
      name        = "Warn everyone else"
      enabled     = true
      mode        = "WARN"
      severity    = "MEDIUM"
      title       = "Careful"
      subtext     = "Torrent sites are discouraged. This visit is recorded."
      button_text = "Continue anyway" # required for WARN

      # Also applies to internal hosts and private IP addresses. Must be false
      # (or omitted) when mode is OFF: the API returns it as false there.
      detect_on_internal_hosts = true
    },
  ]
}
```

With `detections/torrent-website-visit.yaml`:

```yaml
input: web_request
metadata:
  indicator: TORRENT_MAGNET_LINK_DETECTED
conditions:
  request_url:
    scheme: magnet
```

## Schema

### Required

- `detection_logic` (String) The detection logic: one or more YAML documents describing what the browser extension matches on, separated by the standard YAML document separator (`---`). Stored and returned verbatim.

The API accepts at most 10 KiB (10,240 bytes of UTF-8) and at most 100 documents, and plan checks both.
- `name` (String) The detection's name. May contain only letters, numbers, spaces and underscores.

~> A detection cannot be renamed: the API derives its permanent identifier from the name, and neither can change afterwards. Changing `name` therefore replaces the detection: it is destroyed and recreated, and the rules inside it are recreated too and get new identifiers.
- `rules` (Attributes List) The detection's rules, in evaluation order: the first rule that matches wins.

At least one rule is required. This list is the complete set: an apply deletes any rule that is not here. (see [below for nested schema](#nestedatt--rules))

### Read-Only

- `detection_event_type` (String) The detection's permanent identifier, derived by the API from `name`: upper-cased, spaces replaced with underscores, prefixed with `CUSTOM_`. This is the identifier to use when importing.

<a id="nestedatt--rules"></a>
### Nested Schema for `rules`

Required:

- `enabled` (Boolean) Whether the rule is active.
- `mode` (String) What happens when the rule matches. One of `MONITOR`, `WARN`, `BLOCK` or `OFF`.
- `name` (String) A short name to help you recognise the rule. Not required to be unique. At most 250 characters.

Optional:

- `button_text` (String) Label for the message's action button. At most 75 characters. Must not contain `&`, `<` or `>`, which the API stores HTML-escaped.
- `criteria` (Attributes) Restricts the rule to apply only under these conditions. A rule with no criteria applies to everyone. (see [below for nested schema](#nestedatt--rules--criteria))
- `detect_on_internal_hosts` (Boolean) Whether the rule also applies to private IP addresses and internal hosts. Always false for mode `OFF`. Defaults to `false`.
- `key` (String) A stable identifier for this rule, chosen by you and unique within the control. It is never sent to the API; the provider uses it to remember which server-side rule this configuration block corresponds to.

~> Set this on every rule. Rule names are not unique — the console generates names from a template, so duplicates are common — and without `key` the provider has to match rules by position. Reordering positionally matched rules keeps the server-side rule identifiers but moves them onto different rules. Nothing in Push refers to a rule identifier, so the tenant behaves the same either way; set a key if your own tooling reads the identifiers the API returns.
- `severity` (String) The severity of a detection this rule produces. One of `LOW`, `MEDIUM`, `HIGH` or `CRITICAL`.
- `subtext` (String) Message shown to the user. Markdown is supported. At most 1000 characters.
- `title` (String) Heading shown to the user. At most 75 characters. Must not contain `&`, `<` or `>`, which the API stores HTML-escaped.

Read-Only:

- `id` (String) The rule's server-assigned identifier.

## Renaming replaces the detection

The API derives the detection's permanent identifier from its name, and
neither can be changed afterwards, so this provider treats `name` as forcing
replacement: changing it destroys the detection and creates a new one, so the
rules inside it are recreated too and get new identifiers.

## If an apply times out

Creating a detection is not idempotent, so it is not retried after a timeout:
a timeout may mean the detection was created anyway. The next apply
then fails with `CUSTOM_DETECTION_ALREADY_EXISTS`, and the diagnostic gives you
the import block to adopt it.

## Import

```shell
# Custom detections have real identity: import by detection event type, which
# the API derives from the name (upper-cased, spaces to underscores, prefixed
# with CUSTOM_).
terraform import pushsecurity_custom_detection.torrent_website_visit CUSTOM_TORRENT_WEBSITE_VISIT
```

Or with an import block, which also lets Terraform generate the configuration:

```terraform
import {
  to       = pushsecurity_custom_detection.torrent_website_visit
  provider = pushsecurity
  id       = "CUSTOM_TORRENT_WEBSITE_VISIT"
}
```

Remove the `provider` argument before applying — Terraform only accepts it on
import blocks that generate configuration.

Use the `pushsecurity_custom_detections` data source to list what a tenant already has.
