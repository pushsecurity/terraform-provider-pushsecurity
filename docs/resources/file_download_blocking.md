# pushsecurity_file_download_blocking (Resource)

Manages the file download blocking control: which downloads are monitored, warned on or blocked.

~> This resource owns the whole `fileDownloadBlocking` configuration. The API replaces the entire document on every write, so this control is either managed by Terraform or managed in the console — not both. Import the existing configuration before your first apply.

Destroying this resource does not remove the control, which cannot be removed. It writes an empty configuration: no rules, and default control-wide settings.

## Example usage

```terraform
resource "pushsecurity_file_download_blocking" "this" {
  rules = [
    {
      # `key` is provider-side only and never sent to the API. Set one on every
      # rule: it is how the provider tracks which rule is which when you
      # reorder them. Names cannot be used instead — they are not unique.
      key     = "block-executables"
      name    = "Block executables from unapproved sources"
      enabled = true
      mode    = "BLOCK"
      title   = "Download blocked"
      subtext = "Executables from unapproved sites are blocked. Contact IT."

      criteria = {
        file_extensions = { matches = [".exe", ".msi", ".dmg"] }
        url_patterns    = { matches = ["*://*.example.com/*"] }
        # Excludable conditions take an action; include-only ones do not.
        employee_groups = { matches = ["Contractors"], action = "EXCLUDE" }
      }
    },
    {
      key         = "warn-on-archives"
      name        = "Warn on archives"
      enabled     = true
      mode        = "WARN"
      title       = "Careful with archives"
      subtext     = "Archives can hide executables."
      button_text = "Download anyway" # required for WARN, rejected for any other mode

      criteria = {
        file_extensions = { matches = [".zip", ".7z"] }
      }
    },
    {
      # Rules are evaluated in order and the first match wins, so a catch-all
      # belongs last.
      key     = "monitor-everything-else"
      name    = "Monitor everything else"
      enabled = true
      mode    = "MONITOR"
    },
  ]
}
```

<a id="nestedatt--rules"></a>
### Nested Schema for `rules`

Required:

- `enabled` (Boolean) Whether the rule is active.
- `mode` (String) What happens when the rule matches. One of `OFF`, `MONITOR`, `WARN` or `BLOCK`.
- `name` (String) A short name to help you recognise the rule. Not required to be unique. At most 250 characters.

Optional:

- `button_text` (String) Label for the button that lets the user continue past a warning. At most 75 characters. Must not contain `&`, `<` or `>`, which the API stores HTML-escaped.
- `criteria` (Attributes) Restricts the rule to apply only under these conditions. A rule with no criteria applies to everyone. (see [below for nested schema](#nestedatt--rules--criteria))
- `key` (String) A stable identifier for this rule, chosen by you and unique within the control. It is never sent to the API; the provider uses it to remember which server-side rule this configuration block corresponds to.

~> Set this on every rule. Rule names are not unique — the console generates names from a template, so duplicates are common — and without `key` the provider has to match rules by position. Reordering positionally matched rules keeps the server-side rule identifiers but moves them onto different rules. Nothing in Push refers to a rule identifier, so the tenant behaves the same either way; set a key if your own tooling reads the identifiers the API returns.
- `subtext` (String) Message shown to the user. Markdown is supported. At most 1000 characters.
- `title` (String) Heading shown to the user. At most 75 characters. Must not contain `&`, `<` or `>`, which the API stores HTML-escaped.

Read-Only:

- `id` (String) The rule's server-assigned identifier.

### Nested Schema for `rules.criteria`

Optional:

- `employee_groups` (Attributes) Match employees by the groups they belong to. (see [below for nested schema](#nestedatt--rules--criteria--employee_groups))
- `employee_ids` (Attributes) Match specific employees by email address. The provider resolves addresses to the identifiers the API matches on, in both directions, so configuration never holds a UUID. (see [below for nested schema](#nestedatt--rules--criteria--employee_ids))
- `file_extensions` (Attributes) Match downloads by file extension, each a dot followed by the extension, such as `.exe` or `.tar.gz`. Matching ignores case. The API stores extensions in lowercase, so write them that way. (see [below for nested schema](#nestedatt--rules--criteria--file_extensions))
- `file_name_patterns` (Attributes) Match downloads whose file name matches any of these regular expressions. They are JavaScript regular expressions: case-sensitive, unanchored and without flags. To ignore case, use character classes, as in `[Aa]ny[Dd]esk`; to anchor, use `^` and `$`. (see [below for nested schema](#nestedatt--rules--criteria--file_name_patterns))
- `file_names` (Attributes) Match downloads whose file name contains any of these values, ignoring case. A value can match anywhere in the name, so `anydesk` matches `AnyDesk_Setup.exe` and also `AnyDesk_Manual.pdf`. With `action = "EXCLUDE"`, the rule matches every download whose file name contains none of the values. The API stores values in lowercase, so write them that way. (see [below for nested schema](#nestedatt--rules--criteria--file_names))
- `profile_scope` (String) Match by the profile in use on the browser. One of `ALL`, `COMPANY_DOMAIN` or `NON_COMPANY_DOMAIN`. Defaults to `ALL`.
- `url_patterns` (Attributes) Match downloads by URL, using match patterns such as `*://*.example.com/*`. A download matches if a pattern matches the URL it comes from, its referrer, or the URL of the tab it started in. `*.example.com` covers `example.com` and all its subdomains, and a pattern matches every port. The path is case-sensitive and matched in full, so end it with `*` to match what follows: `*://example.com/*` matches every page, but `*://example.com/` only the site root. (see [below for nested schema](#nestedatt--rules--criteria--url_patterns))

## Import

With Terraform 1.14 or later, `terraform query -generate-config-out` writes
the resource and its import block for you, using the `pushsecurity_file_download_blocking` list
resource. Its page shows how.

Import the existing configuration before your first apply, so that the apply is
a no-op rather than a replacement of whatever is already live.

The recommended route is Terraform's own configuration generation:

```terraform
import {
  to       = pushsecurity_file_download_blocking.this
  provider = pushsecurity
  id       = "default"
}
```

Terraform 1.12 and later also accept the resource's identity in place of `id`.
The value is ignored, as the identifier is:

```terraform
import {
  to       = pushsecurity_file_download_blocking.this
  provider = pushsecurity
  identity = { id = "default" }
}
```

```shell
terraform plan -generate-config-out=generated.tf
```

Move the generated resource into your configuration, then **remove the
`provider` argument from the import block** — Terraform only accepts it on
import blocks that generate configuration, and leaving it in place fails the
next plan. Then apply:

```shell
terraform apply
```

The generated configuration has `key = null` on every rule, because keys are
provider-side only and cannot be recovered from the API. Fill them in as part of
adopting the control; the first apply after doing so is a no-op on the API side.

The CLI form also works:

```shell
# Control configurations are singletons: one per control per tenant. The
# identifier is ignored, and the convention is "default".
terraform import pushsecurity_file_download_blocking.this default
```
