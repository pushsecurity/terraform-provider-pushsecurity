# pushsecurity_blocked_urls (Resource)

Manages the tenant's blocked URL list.

~> **A change that removes a pattern rewrites the whole list, and not atomically.** The API offers no bulk replace and no way to remove a single entry, so the provider deletes the entire list and re-adds it one entry at a time. Blocking is degraded while that runs — roughly a second per entry — so such a change to a large list leaves a window in which some or all URLs are not blocked. Plan changes to this resource accordingly. A change that only adds patterns adds just those, and one that only respells patterns the list already holds sends nothing.

This resource owns the whole list: an apply removes any entry not in your configuration, including entries added in the console.

~> **Destroying this resource empties the list.** `terraform destroy` deletes every entry in the tenant's blocked URL list, including entries added in the console. Removing the resource from your configuration does the same.

## Example usage

```terraform
resource "pushsecurity_blocked_urls" "this" {
  # A host, optionally followed by a port and a path. * is a wildcard anywhere
  # in the host or path. Do not include a scheme: the API matches every scheme,
  # and rejects a pattern that names one.
  patterns = [
    "known-bad.example.com",
    "*.phishing.example.net",
    "example.org/malicious/path*",
  ]
}

# The form the API stores and the console displays, which is not accepted as
# input: ["*://known-bad.example.com/*", ...]
output "blocked_urls_as_stored" {
  value = pushsecurity_blocked_urls.this.canonical_patterns
}
```

## Two formats for one value

The API reads and writes this list in different formats, and they are not
interchangeable:

| | Format | Example |
| --- | --- | --- |
| What you write | a pattern | `example.com` |
| What the API stores and returns | canonical | `*://example.com/*` |

Sending the canonical form back is rejected with `Invalid url pattern`, so the
list cannot be written back in the form it is read. The provider converts
between the two, keeps your spelling in `patterns`, and exposes the stored form
as `canonical_patterns`. A canonical pattern written in `patterns` is accepted
and converted the same way.

Some consequences worth knowing:

- `example.com`, `example.com/` and `example.com/*` are the same pattern to the
  API. Having two of them in one configuration is rejected during plan, because
  only one could ever be stored and the plan would never settle.
- A query string or fragment stays part of the path, so `example.com?q=1` is
  stored as `*://example.com/?q=1`.
- A scheme is rejected during plan, as the API rejects it. Write
  `example.com`, not `https://example.com`: every pattern matches every scheme.
- The host is checked during plan against the API's own rules: lower-case
  letters, digits, hyphens and `*`, with at least one letter, or an IPv4
  address, optionally with a port. Since a change that removes a pattern
  rewrites the whole list, a pattern the API rejected at apply could leave the
  list partly written.

## Schema

### Required

- `patterns` (Set of String) The URL patterns to block, as a host optionally followed by a port and a path: `example.com`, `*.example.com`, `example.com/path*`, `intranet:8080/admin`. `*` is a wildcard anywhere in the host or path. The host must be lower case, and the path may carry a query string or fragment, as in `example.com/search?q=*`. A pattern with no path, or with only `/`, blocks every path. At most 2000 patterns.

Do not include a scheme: the API matches every scheme, and rejects a pattern that names one.

A set, because the API does not return entries in the order they were added.

### Read-Only

- `canonical_patterns` (Set of String) The patterns as the API stores them, with the scheme wildcard and an explicit path: `example.com` is stored as `*://example.com/*`. Exposed because this is the form the console and the API's own responses show. A value in this form is also accepted in `patterns`, and is converted to a pattern before it is sent.

## Import

With Terraform 1.14 or later, `terraform query -generate-config-out` writes
the resource and its import block for you, using the `pushsecurity_blocked_urls` list
resource. Its page shows how.

```shell
# One list per tenant, so the identifier is ignored; the convention is "default".
terraform import pushsecurity_blocked_urls.this default
```

In Terraform 1.12 and later, an import block can name the list by its identity
instead. The value is ignored, as the identifier is:

```terraform
import {
  to       = pushsecurity_blocked_urls.this
  identity = { id = "default" }
}
```

Imported state holds the patterns converted back from the canonical form, so
`example.com/*` comes back as `example.com`. Both mean the same thing; adjust
the spelling to taste, as the first plan will be empty either way.
